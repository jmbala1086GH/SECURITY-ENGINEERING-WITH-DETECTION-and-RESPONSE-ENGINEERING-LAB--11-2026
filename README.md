# SECURITY-ENGINEERING-WITH-DETECTION-and-RESPONSE-ENGINEERING-LAB--11-2026
Automated Brute Force Engineering, Detection, and Response with Wazuh SIEM.

During this security operations exercise, an end-to-end detection and automated incident response pipeline was engineered, validated, and documented using Wazuh SIEM (192.168.140.151) to defend an Ubuntu Server (192.168.140.150) hosting a containerized Damn Vulnerable Web Application (DVWA) instance.
An automated HTTP POST credential brute-force simulation was launched from a Kali Linux adversary host (192.168.140.148). Rather than relying solely on standard web access logs, telemetry was extracted from Apache PHP runtime warnings (Undefined index: session_token in /var/www/html/login.php), which revealed automated login requests lacking valid browser session tokens. Custom correlation logic (Rule 100010 and Rule 100011) was authored in Wazuh to detect burst authentication anomalies within a 30-second window and map the activity to MITRE ATT&CK T1110.001 (Brute Force: Password Guessing).
To transition from passive alerting to active defense, Wazuh's firewall-drop Active Response capability was integrated with Rule 100011. Upon detection, the SIEM automatically instructed the target endpoint (jeanpubuntu) to dynamically insert a host-based firewall block against 192.168.140.148 for 120 seconds (Rule 651), halting the attack in real time without manual SOC intervention.

This lab successfully demonstrated the complete lifecycle of modern security operations: adversary emulation, log engineering, custom SIEM rule correlation, and automated SOAR-style containment. By analyzing raw Apache error telemetry generated by automated login scripts against vigilant_hermann, a high-fidelity detection rule (Rule 100011) was built to isolate true credential brute-force attacks from isolated user typos. Coupling this detection with Wazuh's firewall-drop Active Response reduced Mean Time to Respond (MTTR) from minutes of manual analyst triage to milliseconds of automated host isolation, effectively neutralizing the threat from 192.168.140.148 while preserving service availability for legitimate users.
